# 问清楚：新群助手的问题清单

一次只问一个问题，每个问题都附上推荐答案。用户回「行」就按推荐来。已经知道答案的问题跳过。问完把答案写进 部署者私有目录的 `brief.md`，格式见文末。

## 必问（缺一个都没法往下做）

1. **这个助手是给哪个群用的，主要帮大家做什么？用一句话说。**
   推荐：先说一件最常用的事，比如「帮我们找回群里聊过的决定」。其他能力以后再加。
   这个答案决定人设和工具，后面的问题都围绕它展开。

2. **是哪个 Telegram 群？群名叫什么，群里有几个人？**
   推荐：先只做一个群，人少、大家都认识。
   要提醒用户：Bot 只能看到入群之后的消息；群里每个人都能 @ 它。

3. **叫什么名字？**
   - 显示名：推荐「<群简称> 助手」，以后可以用 `/setname` 改。
   - 用户名：必须以 `bot` 结尾，推荐 `<slug>_assistant_bot`，被占用就在中间加几位数字。用户名以后也能改，Hermes 会自动跟着改名后的用户名走。
   - slug：小写英文，用在目录名和 实例标识里。推荐取群简称，比如 `reading-group`。

4. **它该怎么说话？**
   推荐：只在被 @ 或被回复时开口，但会记下群里所有消息，被 @ 时结合前面聊过的内容回答。
   如果用户想让它主动发言，先问清楚在什么情况下发，再提醒一句：主动发言说错了话，全群都会看到。

## 按需问（推荐答案就是「先不接」，用户提到了再展开）

5. **要接哪些资料？**
   推荐：第一版不接，先把群聊这块跑通。要接的话，每一样都要问清楚范围：
   - GitHub：哪几个仓库？只读 token 只授权这几个。
   - Linear：哪个工作区、哪个团队？API key 只勾 Read。
   - 知识库：只接团队范围的。**不接个人知识库**。
   要提醒用户：接上以后，群里任何人 @ 它都能问到这些内容。

6. **要不要定时任务？**
   推荐：第一版不要。要的话问清楚五件事：数据从哪来（推特账号、RSS、群聊总结……）、几点发、推给谁（推荐先只私信给用户本人，稳定了再发到群里）、最多几条、有没有每月预算上限。

7. **除了在群里，谁能私聊它？**
   推荐：只有用户本人。私聊和群是同一个实例，记忆是共用的。

8. **用什么语气？**
   推荐：中文，简洁直接，不卖萌。要有角色感的话，让用户给两三个形容词。

## 配置默认值

- Hermes v0.23.0、Python 3.14，模型账户与预算由部署者确定，模板使用 gpt-6.1-terra。
- 显式指定绝对路径 HERMES_HOME 与 HERMES_REPO，不复用个人实例。
- 群平台只开必要工具，MCP 默认关闭；启用时凭据与端点两层只读。
- 服务器与保活机制由部署环境决定；没有 systemd 时可以用保活循环。
- 秘密存入你的密钥仓库，配置值不进入通用仓库。

## brief.md 格式

```markdown
# <显示名>（<slug>）

- 群：<群名>，<人数> 人
- 用途：<一句话>
- Bot：显示名 <…>，用户名 <…>（未建 / 已建）
- 说话方式：只在被 @ 时回答；记下所有群消息
- 资料：<无 / GitHub: 仓库列表 / Linear: 工作区和团队 / 知识库: 范围>
- 定时任务：<无 / 名称、数据来源、时间、接收人、条数、预算>
- 私聊：<只有用户本人 / …>
- 语气：<…>
- 日期：<YYYY-MM-DD>
```
